Documentation standards for this project:

- All non-trivial functions, classes, and modules must include clear docstrings.
- Docstrings should explain purpose, inputs, outputs, and side effects.
- Prefer concise, technical language over prose.
- Avoid redundant comments that restate obvious code behavior.
- When modifying existing code, update documentation if behavior changes.
- New modules must include a brief top-level description explaining their role in the system.
- Documentation should reflect actual implementation, not intent or future plans.
